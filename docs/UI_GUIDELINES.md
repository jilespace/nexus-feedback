# UI 设计规范

## 设计方向

Nexus Feedback 的界面要现代化、精致、优雅，并且有足够的信息密度。不能做成
只有输入框和按钮的过度极简界面，也不能为了装饰牺牲管理效率。

设计气质：

- 现代 SaaS 产品，而不是营销落地页。
- 美观、完整、有层次，不是空白极简。
- 行动入口清晰，状态反馈明确。
- 管理后台适合高频使用，信息密度足够。
- 加载、空状态、错误、成功、禁用状态都要完整设计。

## 视觉语言

- 使用一个主色、一个强调色和中性色面，避免整套界面只有单一色相。
- 使用克制的边框、层次化表面、轻阴影和清晰 focus ring。
- 卡片用于重复项和聚焦面板，不要卡片套卡片。
- 圆角建议 8-14px，小控件比大面板更收敛。
- 操作按钮可使用图标辅助扫描。
- hover、active、focus、loading、success 等微交互要有设计感。

## 管理后台

管理后台是操作型工具，优先保证扫描效率和决策效率。

必须具备：

- 稳定的侧边或顶部导航。
- 反馈列表上方有概要指标。
- 筛选栏包含状态、分类、优先级、时间范围、搜索。
- 表格或高密度列表至少能舒适展示 20 行。
- 选中、hover、加载、空状态、错误状态清晰可见。
- 详情面板或详情页展示状态控制、metadata、附件、回复。

有助于客服和排查的标识、时间戳可以展示；纯技术实现细节默认隐藏，除非对诊断
有帮助。

## 公开提交页

公开提交页需要亲和、可信、精致。

必须具备：

- 首屏能看到产品或工作区身份。
- 表单留白充足但不松散。
- 校验信息具体，并靠近对应字段。
- 成功状态说明已经发生什么、用户接下来可以期待什么。
- 附件上传过程可见，让用户有确定感。

## Widget

Widget 要像宿主产品的一部分一样可信，同时又足够醒目。

必须具备：

- launcher 有清晰图标，并提供标签或 tooltip。
- 弹窗或浮层有完整 focus 管理。
- 表单紧凑但不拥挤。
- 成功和错误状态必须是完整视觉状态，不能只有一行文字。
- 主题变量支持品牌色、圆角和密度。

## 字体与排版

- 使用易读的无衬线字体。
- 不用 viewport width 直接缩放字体。
- letter spacing 默认为 `0`，除非设计 token 明确要求。
- 紧凑面板使用紧凑标题；大字号只用于真正的页面标题或公开页首屏。

## 响应式

- 管理后台优先保证笔记本和桌面端效率，再适配移动端。
- 公开提交页和 Widget 必须在移动端顺畅可用。
- 文本不能溢出按钮、徽标、卡片或弹窗标题。
- 固定格式元素需要稳定尺寸，避免 hover、标签或动态内容导致布局跳动。

## 可访问性

- 表单、弹窗、菜单、筛选、状态变更必须支持键盘操作。
- focus 状态必须可见。
- 颜色不能作为唯一状态信号。
- 弹窗需要 trap focus，关闭后恢复焦点。
- 表单字段必须有可访问标签。
